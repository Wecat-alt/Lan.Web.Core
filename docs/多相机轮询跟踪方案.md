# 多相机时间轮询跟踪多目标

> 2026-07-27 实施完成，单相机测试通过。

## 问题

`WDefenceArea.trackTargetPath()` 原本只使用 `cameras[0]`，所有雷达目标打包成数组传给一台相机的 RBTrack channel，由 SDK 内部自行选择跟踪哪个目标。防区绑定多台相机时其余相机完全闲置。

## 方案

改为 **C# 侧选择目标 + SDK 只接收单个目标 + 时间轮询**。

### 轮询规则

每 15 秒轮换一次目标分配，公式：

```
targetIdx = (assignedCount + trackRound × trackingCameraCount) % targetCount
```

| 变量 | 含义 |
|------|------|
| `assignedCount` | 当前相机在"启用跟踪的相机"中的序号（0, 1, 2...），非 `camIdx` |
| `trackingCameraCount` | `IsTrack == 1` 的相机数量 |
| `trackRound` | 轮次，每 15 秒 +1 |

示例 — 5 目标 + 2 相机(IsTrack=1)：

```
Round 0 ( 0~15s): 相机0→T0, 相机1→T1
Round 1 (15~30s): 相机0→T2, 相机1→T3
Round 2 (30~45s): 相机0→T4, 相机1→T0
Round 3 (45~60s): 相机0→T1, 相机1→T2 ...
```

### SDK 调用变化

```
改前: RBTRACK_UpdateTargets(channelId, RADAR_TARGETS_T[], targetNum)  // SDK 自选
改后: RBTRACK_UpdateTargets(channelId, ref RADAR_TARGETS_T, 1)        // C# 侧选定
```

P/Invoke 声明从数组参数改为 `ref` 结构体。

### 关键设计决策

| 决策 | 原因 |
|------|------|
| 目标不够时多余相机不动 | `assignedCount >= trackCount` 时 `break`，避免两个相机抢同一目标 |
| 目标变化时不重置计时器 | 安防场景目标频繁变化，重置会导致轮换无限推迟。只重置 `_trackRound` |
| IsTrack=0 不参与轮询 | `trackingCameraCount` 和 `assignedCount` 都跳过 |
| 每个相机只传一个目标给 SDK | 跟踪选择逻辑完全由 C# 控制 |

## 修改的文件

### 1. `Lan.ServiceCore/TargetCollection/WDefenceArea.cs`

**新增字段：**
```csharp
const int RotationIntervalSeconds = 15;
private int _trackRound = 0;
private DateTime _lastTargetRotationTime;
private HashSet<int> _lastTargetIds = new HashSet<int>();
```

**trackTargetPath() dispatch 逻辑：**
```csharp
if (cameras.Length == 0 || _list_RBTRACK?.Count == 0)
    continue;

// 检测目标变化 → 重置 round（不重置计时器）
var currentTargetIds = new HashSet<int>();
for (int i = 0; i < tarItem.Count; i++)
    currentTargetIds.Add(tarItem[i].TargetId);

if (!_lastTargetIds.SetEquals(currentTargetIds))
{
    _trackRound = 0;
    _lastTargetIds = currentTargetIds;
}

// 检查轮换时间
if ((DateTime.Now - _lastTargetRotationTime).TotalSeconds >= RotationIntervalSeconds)
{
    _trackRound++;
    _lastTargetRotationTime = DateTime.Now;
}

// 分配目标
int trackingCameraCount = cameras.Count(c => c.IsTrack == 1);
int trackCount = Math.Min(trackingCameraCount, tarItem.Count);
int assignedCount = 0;

for (int camIdx = 0; camIdx < cameras.Length; camIdx++)
{
    if (cameras[camIdx].IsTrack != 1) continue;
    if (assignedCount >= trackCount) break;

    int targetIdx = (assignedCount + _trackRound * trackingCameraCount) % tarItem.Count;

    for (int j = 0; j < _list_RBTRACK.Count; j++)
    {
        if (_list_RBTRACK[j].CameraIp == cameras[camIdx].Ip
            && _list_RBTRACK[j].DefenceareaId == tarItem[0].AreaId.ToString()
            && _list_RBTRACK[j].channelId != -1)
        {
            RADAR_TARGETS_T target = new RADAR_TARGETS_T();
            target.targetId = tarItem[targetIdx].TargetId;
            target.type     = (uint)tarItem[targetIdx].TargetType;
            target.speed_X  = float.Parse(tarItem[targetIdx].SpeedX);
            target.speed_Y  = float.Parse(tarItem[targetIdx].SpeedY);
            target.cod_X    = tarItem[targetIdx].AxesX;
            target.cod_Y    = tarItem[targetIdx].AxesY;
            target.cod_Z    = tarItem[targetIdx].AxesZ;
            target.distance = float.Parse(tarItem[targetIdx].Distance);
            target.azimuth  = float.Parse(tarItem[targetIdx].AzimuthAngle);

            RBTrackSdk.RBTRACK_UpdateTargets(_list_RBTRACK[j].channelId, ref target, 1);
            break;
        }
    }
    assignedCount++;
}
```

## 边界场景覆盖

| 场景 | 行为 |
|------|------|
| 5目标 + 2相机(都IsTrack=1) | 两个相机各自轮询，不重复 |
| 1目标 + 2相机(都IsTrack=1) | 只有相机0跟踪，相机1不动 |
| 3目标 + 2相机(camera[0] IsTrack=0) | 仅相机1逐个轮询3个目标 |
| 新目标中途出现 | round=0 重新分配，计时器不重置 |
| 目标消失 | round=0 重新分配，计时器不重置 |

## 后续可调整

- 轮询间隔当前为常量 15 秒，可改为配置项
- 当前为简单轮询，未考虑目标优先级（距离、威胁等级等）
- 可考虑按目标距离就近分配给相机
