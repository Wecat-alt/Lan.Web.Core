### 1.1 SQL 注入漏洞

**涉及文件：**

| `CameraService.cs` | 130 | `$"UPDATE camera SET istrack = {istrack} WHERE ID = '{id}'"` |

| `CalibrationService.cs` | 141 | `$"UPDATE calibration SET CalibrationDistance = {CalibrationDistance}..."` |

**修复方式：** 全部改用 SqlSugar 的表达式更新 API：

```csharp
int i = Update(w => w.Id == id, it => new CameraModel { IsTrack = istrack });
```

### 1.2 Worker 内存泄漏 — 去重字典无限增长

**文件：** `Lan.ServiceCore/Signalr/Worker.cs:21`

```csharp
ConcurrentDictionary<int, string> _dictSpeedFX = new();
```

这个字典用于"同秒去重"（按 `mmss` 格式比较时间），但**从未清理过期条目**。随着新目标 ID 不断出现（雷达每次扫描可能产生新的目标 ID），字典会无限增长，最终导致 OOM。

**更严重的是去重逻辑有 Bug：** 键是 `TargetId`，值是 `mmss` 字符串。两个不同目标如果在同一秒到达，第二个目标的数据会被错误跳过，因为比较的是时间而非 (TargetId, Time) 的组合。

**修复方式：**

```csharp 
// 方案一：定期清理（简单）
// 每 30 秒扫描一次，移除 60 秒未更新的条目
private DateTime _lastCleanup = DateTime.UtcNow;
if ((DateTime.UtcNow - _lastCleanup).TotalSeconds > 30)
{
    var threshold = DateTime.UtcNow.AddSeconds(-60).ToString("mmss");
    foreach (var key in _dictSpeedFX.Where(kv => string.Compare(kv.Value, threshold) < 0).Select(kv => kv.Key))
        _dictSpeedFX.TryRemove(key, out _);
    _lastCleanup = DateTime.UtcNow;
}

// 方案二：改用 MemoryCache（推荐）
private readonly MemoryCache _cache = new(new MemoryCacheOptions());
// 写入时设置绝对过期
_cache.Set(tarItem.TargetId, tarItem.DateTime, TimeSpan.FromSeconds(5));
```

### 1.3 中间件管道顺序错误

**文件：** `Lan.Application/Program.cs:182-235`

```csharp
// ❌ 当前顺序（有严重问题）
app.UseCors(opt => { ... });              // 第182行：第一次 CORS
// ... 初始化代码 ...
app.UseHttpsRedirection();                // 第208行
app.UseAuthorization();                   // 第210行：只有授权，没有认证！
app.UseCors("AllowSpecificOrigin");       // 第213行：第二次 CORS，名称未注册！
app.UseRouting();                         // 第215行：Routing 应该在 CORS 之前
app.UseEndpoints(...);                    // 第216行
app.Use(async (context, next) => { ... }); // 第220行：异常处理在最后
app.MapControllers();                     // 第233行
```

**问题清单：**

1. `UseRouting()` 必须在 `UseCors()` 和 `UseAuthorization()` **之前**
2. `"AllowSpecificOrigin"` 策略从未注册，`UseCors("...")` 无效
3. 缺少 `UseAuthentication()`（只有 `UseAuthorization()` 是不够的）
4. 全局异常处理中间件过于简陋：只返回纯文本 `"An error occurred"`，无日志记录

**修复后：**

```csharp

app.UseExceptionHandler(exceptionHandlerApp =>
{
    exceptionHandlerApp.Run(async context =>
    {
        context.Response.StatusCode = 500;
        context.Response.ContentType = "application/json";
        var error = new { code = 500, msg = "Internal Server Error" };
        await context.Response.WriteAsync(JsonSerializer.Serialize(error));
    });
});

app.UseHttpsRedirection();
app.UseRouting();
app.UseCors(opt => opt.WithOrigins(corsOrigins).AllowAnyHeader().AllowAnyMethod().AllowCredentials());
app.UseAuthentication();    // ← 需要添加
app.UseAuthorization();
app.MapHub<MessageHub>("/hubs/stock");
app.MapControllers();
```

### 1.4 GlobalVariable 线程安全问题

**文件：** `Lan.ServiceCore/Public/GlobalVariable.cs:8-13`

```csharp
public static bool TrackStatus { get; set; } = true;  // 多线程读写，无同步
public static string FilePath { get; set; }             // 同上
public static string recordservicehost { get; set; }    // 同上
```

`TrackStatus` 在多个 Service 方法中被改为 `false` 然后 `true`（如 `RadarService.UpdateRadar` 第 142/149 行、`CameraService.UpdateCamera` 第 117/121 行）。多个请求同时操作时存在竞态条件 — 线程 A 设置为 `false` 后，线程 B 在 A 执行完毕前也可能设置为 `false`，导致其中一个的 `true` 恢复丢失。

**修复方式：**

```csharp
// 方案一：最简单 — 只在当前 Service 方法内局部控制，不用全局变量
// 方案二：至少加 volatile
public static volatile bool TrackStatus = true;
// 方案三：更好 — 移除全局变量，每个 Service 方法内局部控制
```

## 2. 性能优化

### 2.1 每次 HTTP 请求都创建 JsonSerializerSettings

**文件：** `Lan.Infrastructure/Controller/BaseController.cs:30-37`

```csharp
// ❌ 每个请求都 new — CamelCasePropertyNamesContractResolver 内部有反射缓存
private static string GetJsonStr(ApiResult apiResult, string timeFormatStr)
{
    var serializerSettings = new JsonSerializerSettings
    {
        ContractResolver = new CamelCasePropertyNamesContractResolver(),  // 反射开销
        DateFormatString = timeFormatStr
    };
    return JsonConvert.SerializeObject(apiResult, Formatting.Indented, serializerSettings);
}
```

**修复：** `JsonSerializerSettings` 是线程安全的，缓存为 static：

```csharp
private static readonly JsonSerializerSettings DefaultSettings = new()
{
    ContractResolver = new CamelCasePropertyNamesContractResolver(),
    DateFormatString = "yyyy-MM-dd HH:mm:ss"
};
```

**影响：** 每次 HTTP 请求节省一次反射初始化 + 对象分配。生产环境每秒数百请求时差异显著。

### 2.2 Worker 使用 Formatting.Indented 推送实时数据

**文件：** `Lan.ServiceCore/Signalr/Worker.cs:60,69`

```csharp
string json = JsonConvert.SerializeObject(tarItem, Formatting.Indented, serializerSettings);
await _messageHub.Clients.All.SendAsync("ReceiveTargetData", json);
```

这是**每 10ms** 向所有连接客户端推送的雷达实时目标数据。使用缩进格式化会让每条 JSON 消息增加 30-50% 的空白字符。如果 10 个客户端 × 200 目标/秒，网络带宽被大量空格和换行浪费。

**修复：** `Formatting.None`，或改用 `System.Text.Json`（比 Newtonsoft 快 2-4 倍）：

```csharp
string json = JsonSerializer.Serialize(tarItem);  // System.Text.Json，默认无缩进
```

### 4.6 迁移 Newtonsoft.Json → System.Text.Json

**理由：**

- `System.Text.Json` 比 Newtonsoft 快 2-4 倍
- GC 分配少得多
- .NET 10 的原生序列化器，ASP.NET Core 默认使用
- 项目同时引用了两个库，混用增加依赖

**迁移步骤：**

1. 全局配置 `builder.Services.AddControllers().AddJsonOptions(...)`
2. `BaseController` 中 `JsonConvert.SerializeObject` → `JsonSerializer.Serialize`
3. `Worker.cs` / `AlarmBackgroundService.cs` 中的 `JsonConvert.SerializeObject` → `JsonSerializer.Serialize`
4. `[JsonProperty]` → `[JsonPropertyName]`
5. `[JsonIgnore]`（Newtonsoft）→ `[JsonIgnore]`（System.Text.Json）
