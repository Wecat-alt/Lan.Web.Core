# 雷达组网实施方案：坐标系统一 + 目标融合

## Context

当前系统支持一个防区绑定多个雷达，但每个雷达独立计算 GPS 坐标（以自身 Lat/Lng 为原点做大地线变换），没有统一的坐标参考系。当两个雷达有重叠探测区域时，同一个物理目标会被两个雷达分别上报，导致：

1. 前端地图上出现两个"幽灵"标记（同一物体两个位置）
2. 可能产生重复报警
3. 无法利用多雷达覆盖提升探测精度

`WRadar` 中已有 `X`、`Y`、`Orientation`、`InvertX` 字段（注释标注"雷达相对防区的偏移"），`RadarTargetItem` 构造函数中有完整的多雷达坐标旋转+平移代码，但**均未接入当前管线**。

---

## 架构决策

### 决策 1：以主雷达为坐标原点

操作员从防区绑定的雷达中**指定一台为主雷达**。主雷达的位置就是坐标原点 (X=0, Y=0)，其他（从）雷达的标定偏移全部相对于主雷达。

```
主雷达 (Master)：X=0, Y=0, Orientation=0, InvertX=false [不可编辑]
    → 目标直接用主雷达的 GPS + NorthDeviationAngle 变换

从雷达 (Slave)：需要标定 OffsetX, OffsetY, Orientation, InvertX
    → 目标先标定到主雷达坐标系，再用主雷达的 GPS 变换
```

**变换流程**：

```
— 主雷达目标 —
  原始(AxesX, AxesY) → TransformLatLon(主雷达 GPS, NorthDeviationAngle)
  → GPS 坐标

— 从雷达目标 —
  原始(AxesX, AxesY)
    │
    ▼ ApplyRadarCalibration()
    │  1. InvertX? → 镜像
    │  2. 旋转 Orientation 度
    │  3. 平移 OffsetX/OffsetY
    │
    ▼
  主雷达坐标系中的 (X', Y')
    │
    ▼ TransformLatLon(主雷达 GPS, 主雷达 NorthDeviationAngle)
    │
    ▼
  GPS 坐标 — 与主雷达目标在同一坐标空间
```

**向后兼容**：如果防区没有指定主雷达（MasterRadarId = 0），所有雷达各自独立计算 → 和现在的行为完全相同。

### 决策 2：目标融合放在 Stage 3 之后、Stage 4 之前

```
Stage 1: QuickFilter → Stage 2: Transform（含标定）→ Stage 3: PolygonFilter
                                                                   │
                                                                   ▼
                                                        [NEW] Stage 3.5: Fusion
                                                                   │
                                                                   ▼
                                                             Stage 4: Dispatch
```

### 决策 3：防区级缓冲 + 定时冲刷

当前 `TargetDetectCallback` 按雷达逐个触发。通过 `WDefenceArea` 层的缓冲队列 + 80ms 冲刷定时器，等所有雷达数据到齐后统一处理 + 融合。

### A.3 核心变换逻辑

**文件**：`Lan.ServiceCore/TargetCollection/TargetCollection.cs`

**新增方法**：`ApplyRadarCalibration` — 将从雷达本地坐标转换到主雷达坐标系

```csharp
/// <summary>
/// 将从雷达本地坐标 (axesX, axesY) 转换到主雷达坐标系。
/// 变换链：X轴镜像 → 旋转 → 平移偏移
/// </summary>
private static (float mx, float my, float msx, float msy) ApplyRadarCalibration(
    float axesX, float axesY, float speedX, float speedY,
    float offsetX, float offsetY, float orientationDeg, bool invertX)
{
    float lx = invertX ? -axesX : axesX;
    float ly = axesY;

    float rad = orientationDeg * MathF.PI / 180f;
    float c = MathF.Cos(rad), s = MathF.Sin(rad);

    // 旋转 + 平移（旋转矩阵 CCW）
    float mx = lx * c - ly * s + offsetX;
    float my = lx * s + ly * c + offsetY;
    float msx = speedX * c - speedY * s;
    float msy = speedX * s + speedY * c;

    return (mx, my, msx, msy);
}
```

**修改 `AddTarget` / `ProcessBufferedRadars` 中 Stage 2 的逻辑**：

```csharp
// 获取主雷达（如果配置了的话）
WRadar? masterRadar = null;
int masterRadarId = DefenceArea.MasterRadarId;
if (masterRadarId > 0)
    masterRadar = RadarManager.GetInstance().GetById(masterRadarId);

foreach (var radar in radars)
{
    // ... Stage 1: QuickFilter ...

    // 决定用什么 GPS 做大地线变换
    WRadar refRadar;       // 参考雷达（GPS 来源）
    float northDev;        // 北偏角
    float calibratedX, calibratedY;  // 变换后的坐标

    bool isMaster = (masterRadar != null && radar.Ip == masterRadar.Ip);

    if (masterRadar == null || isMaster)
    {
        // 无主雷达 或 当前就是主雷达 → 直接用自身坐标
        refRadar = radar;
        northDev = double.Parse(radar.NorthDeviationAngle);
        calibratedX = tar.X;
        calibratedY = tar.Y;
    }
    else
    {
        // 从雷达 → 标定到主雷达坐标系
        var (mx, my, msx, msy) = ApplyRadarCalibration(
            tar.AxesX, tar.AxesY, tar.SpeedX, tar.SpeedY,
            radar.X, radar.Y, radar.Orientation, radar.InvertX);
        refRadar = masterRadar;
        northDev = double.Parse(masterRadar.NorthDeviationAngle);
        calibratedX = mx;
        calibratedY = my;
    }

    // 用统一的大地线变换（和现有 TransformLatLon 逻辑一致）
    var (lat, lng) = TransformLatLon(
        latRad, lonRad, cosLat, sinLat, northDev,
        calibratedX, calibratedY, tar.AzimuthAngle);

    // ... Stage 3: PolygonFilter ...
}
```

**关键点**：
- `TransformLatLon` **不需要修改**——它的逻辑（`bearing = NorthDev + AzimuthAngle`，从参考点 GPS 出发做大圆计算）完全保持不变
- 从雷达的目标经过标定后，`calibratedX/calibratedY` 已经是主雷达坐标系中的位置，把它当作主雷达的"本地坐标"输入 `TransformLatLon` 即可
- 主雷达的目标完全跳过标定步骤，和现有行为一致

## Part B：目标融合

### B.1 防区级缓冲机制

**文件**：`Lan.ServiceCore/TargetCollection/WDefenceArea.cs`

```csharp
private readonly ConcurrentQueue<WRadar> _pendingRadarQueue = new();
private Timer? _flushTimer;
private const int FLUSH_DELAY_MS = 80;
```

修改 `AddAlarmTarget`：

```csharp
internal bool AddAlarmTarget(WRadar radar)
{
    _pendingRadarQueue.Enqueue(radar);
    _flushTimer?.Change(FLUSH_DELAY_MS, Timeout.Infinite);
    _flushTimer ??= new Timer(_ => FlushPendingRadars(),
        null, FLUSH_DELAY_MS, Timeout.Infinite);
    return true;
}
```

新增 `FlushPendingRadars`：清空队列 → 去重（同一雷达多次入队取最新）→ 调用 `TargetCollection.ProcessBufferedRadars`。

### B.2 批量处理 + 融合方法

**文件**：`Lan.ServiceCore/TargetCollection/TargetCollection.cs`

新增内部类 `PendingTarget`（Stage 3 通过后的中间状态）：

```csharp
private class PendingTarget
{
    public WRadar Radar;
    public double Lat, Lng;
    public float CalibratedX, CalibratedY;
    public float SpeedX, SpeedY;
    public float Distance;
    public int TargetId;
    public uint TargetType;
    public float Snr;
    public DateTime Now;
    public string Utime;
}
```

新增 `ProcessBufferedRadars`：遍历所有缓冲雷达 → Stage 1→2→3（使用 Part A 的标定逻辑）→ 收集 `PendingTarget` → `FusionEngine.Fuse()` → `DispatchFusedTarget`。

### B.3 融合算法（不变）

**新文件**：`FusionEngine.cs` + `FusedTarget.cs`

- Union-Find 聚类，O(n²)，空间距离阈值 5m
- 仅融合**不同雷达**的目标（同一雷达自身检测不融合）
- 运动方向检查：速度向量点积 > 0
- 按 SNR 加权平均 GPS，按来源雷达 ID 确定性生成融合 ID（> 10,000,000）

### B.4 SendMS 扩展 + Worker 去重

- `SendMS` 新增：`IsFused`、`SourceTargetIds`、`SourceRadarIps`
- `Worker.cs` 去重 Key 改为 `"{AreaId}_{TargetId}"`
